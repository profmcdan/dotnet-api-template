How to run this project on macOS and Windows. To install it as a reusable `dotnet new` template

toc::[]

== Prerequisites

[cols="2,1,3", options="header"]
|===
| Tool | Version | Needed for

| .NET SDK          | 10.0+  | Building, testing, EF tooling
| Docker Desktop    | 4.30+  | The Compose stack and the integration tests
| Git               | any    | Cloning
| `jq`              | any    | Optional, for the curl examples
|===

Everything else - PostgreSQL, Redis, Redpanda, a mail catcher - runs in containers. Nothing needs
to be installed on the host.

=== macOS

[source,bash]
----
brew install --cask dotnet-sdk
brew install --cask docker
brew install jq
----

Start Docker Desktop once so the daemon is running, then check:

[source,bash]
----
dotnet --version    # 10.0.x or later
docker info         # must not error
----

On Apple Silicon every image used here has a native `arm64` build, so nothing runs under
emulation.

=== Windows

Use winget from PowerShell:

[source,powershell]
----
winget install Microsoft.DotNet.SDK.10
winget install Docker.DockerDesktop
winget install jqlang.jq
----

Docker Desktop needs the WSL 2 backend. If it is not already enabled, from an *administrator*
PowerShell:

[source,powershell]
----
wsl --install
----

Restart, start Docker Desktop, and confirm it reports "Engine running". Then:

[source,powershell]
----
dotnet --version
docker info
----

[TIP]
====
Line endings: this repository ships an `.editorconfig` that sets `end_of_line = lf`. If Git is
configured with `core.autocrlf=true`, shell scripts copied into containers can gain CRLF endings
and fail with `no such file or directory`. Either set `core.autocrlf=input` or work inside WSL.
====

== Configure

[source,bash]
----
git clone <your-repository-url>
cd <repository>
cp .env.sample .env
----

`.env.sample` documents every setting. Three of them matter before you start:

[cols="2,3", options="header"]
|===
| Key | What to set

| `JWT__SIGNINGKEY`
| At least 32 characters. Generate one: `openssl rand -base64 48` (macOS/Linux) or
  `[Convert]::ToBase64String((1..48 \| % { Get-Random -Max 256 }))` (PowerShell).

| `POSTGRES_PASSWORD`
| Anything for local work. It must match the password inside `DATABASE__CONNECTIONSTRING`.

| `MIGRATOR__SEEDADMINEMAIL` / `MIGRATOR__SEEDADMINPASSWORD`
| The bootstrap administrator. Created only when the users table is empty. The password must pass
  the policy: 12+ characters, a letter, a digit or symbol, and no well-known phrases.
|===

Keys use the ASP.NET Core convention - `Section__Key` maps onto configuration `Section:Key`. A
real environment variable always beats the value in `.env`, so CI and production can override
anything without editing the file.

`.env` is git-ignored. Do not commit it.

== Run with Docker

[source,bash]
----
docker compose up -d
----

First run takes a few minutes to build three images. Then:

[source,bash]
----
docker compose ps
----

[listing]
----
SERVICE            STATUS
api                Up (healthy)
mailpit            Up (healthy)
postgres           Up (healthy)
redis              Up (healthy)
redpanda           Up (healthy)
redpanda-console   Up
worker             Up (healthy)
----

`migrator` will show as `Exited (0)` - that is correct, it is a run-to-completion job. Check what
it did:

[source,bash]
----
docker compose logs migrator
----

You should see the schema applied, eight topics created under your prefix, and the administrator
seeded.

=== What is now listening

|===
| Service | URL | Notes

| API              | http://localhost:5080          | `API_HTTP_PORT`
| API reference    | http://localhost:5080/scalar/v1 | Development only
| Liveness         | http://localhost:5080/health/live | Checks nothing external, by design
| Readiness        | http://localhost:5080/health/ready | Postgres, Redis, Kafka
| Worker health    | http://localhost:5081/health/ready |
| Redpanda Console | http://localhost:8085          | Browse topics and messages
| Mailpit          | http://localhost:8025          | Every outbound email
| Postgres         | localhost:5432                 |
| Redis            | localhost:6379                 |
| Kafka            | localhost:19092                | External listener for host tools
|===

Change any port in `.env` if it collides with something you already run.

=== Verify the invite flow

[source,bash]
----
API=http://localhost:5080

TOKEN=$(curl -s -X POST $API/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"change-me-immediately-1"}' | jq -r .accessToken)

curl -s -X POST $API/api/v1/users/invitations \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","fullName":"Ada Lovelace","roles":["member"]}' | jq
----

Open http://localhost:8025 - the invitation is there, with a working "Accept your invitation"
button. Follow it, or extract the token and accept over the API:

[source,bash]
----
curl -s -X POST $API/api/v1/auth/invitations/accept \
  -H 'Content-Type: application/json' \
  -d '{"token":"<token>","password":"analytical-engine-1843","fullName":"Ada King"}' | jq
----

While that happens you can watch `<prefix>.user.invited` and `<prefix>.email.requested` fill up in
Redpanda Console.

=== Everyday commands

[source,bash]
----
docker compose logs -f api worker      # follow
docker compose restart api             # restart one service
docker compose build api && docker compose up -d api   # rebuild after a code change
docker compose run --rm migrator                       # re-run all bootstrap steps
docker compose run --rm migrator kafka-topics          # re-run one step
docker compose down                    # stop, keep data
docker compose down -v                 # stop and delete volumes (full reset)
----

== Run without Docker

Useful for debugging and hot reload. Infrastructure still runs in containers; the .NET services
run on the host.

[source,bash]
----
docker compose up -d postgres redis redpanda mailpit
----

Point `.env` at localhost - container hostnames do not resolve from the host:

[source,ini]
----
DATABASE__CONNECTIONSTRING=Host=localhost;Port=5432;Database=appdb;Username=appuser;Password=<yours>
REDIS__CONNECTIONSTRING=localhost:6379
KAFKA__BOOTSTRAPSERVERS=localhost:19092
EMAIL__SMTPHOST=localhost
----

`localhost:19092` is Redpanda's external listener, advertised for exactly this.

Then, in three terminals:

[source,bash]
----
dotnet run --project src/CleanArchTemplate.Migrator     # once
dotnet run --project src/CleanArchTemplate.Api
dotnet run --project src/CleanArchTemplate.Worker
----

The API is on http://localhost:5080 with the reference at `/scalar/v1`. `dotnet watch` works
normally.

[NOTE]
====
`.env` is read by the `DotEnv` loader in `Infrastructure.Configuration`, which walks up from the
binary's directory looking for the file. Compose injects the same keys as real environment
variables, so both paths behave identically.
====

== Database migrations

Migrations live in `Infrastructure/Persistence/Migrations`; `Migrator` is the startup project.
The `dotnet-ef` tool is pinned in `.config/dotnet-tools.json`:

[source,bash]
----
dotnet tool restore

dotnet dotnet-ef migrations add AddSomething \
  --project src/CleanArchTemplate.Infrastructure \
  --startup-project src/CleanArchTemplate.Migrator \
  --output-dir Persistence/Migrations
----

The design-time factory reads `DATABASE__CONNECTIONSTRING` or `ConnectionStrings__Default`, and
falls back to a local default, so adding a migration never needs the full host to start.

Apply them by running the migrator - never from API startup, where several replicas would race:

[source,bash]
----
dotnet run --project src/CleanArchTemplate.Migrator
# or
docker compose run --rm migrator
----

To undo the most recent, unapplied migration:

[source,bash]
----
dotnet dotnet-ef migrations remove \
  --project src/CleanArchTemplate.Infrastructure \
  --startup-project src/CleanArchTemplate.Migrator
----

== Tests

[source,bash]
----
dotnet test CleanArchTemplate.slnx                          # everything
dotnet test tests/CleanArchTemplate.Domain.UnitTests        # no Docker needed
dotnet test tests/CleanArchTemplate.Application.UnitTests   # no Docker needed
dotnet test tests/CleanArchTemplate.Api.IntegrationTests    # needs Docker
----

The integration tests start their own PostgreSQL, Redis and Redpanda containers via
Testcontainers, independent of the Compose stack - you can run both at once. If Docker is not
available they *skip* rather than fail.

With coverage:

[source,bash]
----
dotnet test CleanArchTemplate.slnx --collect:"XPlat Code Coverage"
----

== Troubleshooting

[cols="2,3", options="header"]
|===
| Symptom | Cause and fix

| `dependency failed to start: container … is unhealthy`
| A dependency did not pass its health check. `docker compose logs <service>` names the reason.

| Migrator exits non-zero with a connection error
| Postgres was not ready. It retries for `MIGRATOR__STARTUPTIMEOUTSECONDS`; raise it on a slow
  machine, or check `POSTGRES_PASSWORD` matches the password inside `DATABASE__CONNECTIONSTRING`.

| API starts, every request returns 500 mentioning `SymmetricSecurityKey`
| `JWT__SIGNINGKEY` is empty or shorter than 32 characters.

| `Kafka topics are missing` in the worker log
| The migrator has not run, or `KAFKA__TOPICPREFIX` differs between services. Run
  `docker compose run --rm migrator kafka-topics`.

| Consumers connect but never receive anything
| Almost always a prefix mismatch. Compare the topic names in Redpanda Console against
  `KAFKA__TOPICPREFIX`.

| No email in Mailpit
| Check the outbox: `docker compose exec postgres psql -U appuser -d appdb -c
  "select topic, processed_at, last_error from outbox_messages order by occurred_at desc limit 5;"`.
  A null `processed_at` with a `last_error` means the publish is failing; a published row with no
  email means the consumer is failing - see `docker compose logs worker`.

| Login always returns 401 with correct credentials
| The account may not be `Active`, or `SECURITY__MAXFAILEDLOGINATTEMPTS` has been hit. The lockout
  clears after `SECURITY__LOCKOUTWINDOWMINUTES`, or immediately with
  `docker compose exec redis redis-cli FLUSHDB`.

| Requests start returning 401 after an admin action
| Working as intended: role changes, suspension and password changes bump the security stamp and
  invalidate existing access tokens. Refresh or sign in again.

| Port already allocated
| Change the `*_PORT` value in `.env` and `docker compose up -d` again.

| Integration tests fail with a Docker socket error
| Docker Desktop is not running. Start it, or run only the unit test projects.

| Build fails on `protoc` inside Docker
| Only relevant if you switched the build stage to an Alpine SDK. `Grpc.Tools` ships a
  glibc-linked `protoc` with no musl build; keep the Debian SDK stage.

| Everything is confusing and you want a clean slate
| `docker compose down -v && docker compose up -d --build`
|===

== Uninstall

[source,bash]
----
docker compose down -v                 # containers, network and volumes
docker image rm cleanarch-api cleanarch-worker cleanarch-migrator
----
